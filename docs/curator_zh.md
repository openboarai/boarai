# 后台整理（core/curator）

防止自我改进存储腐烂的后台整理：粗定时器驱动的全局教训去重。

## 当前职责

一轮整理做一件事：`pod://global` 里共享同一 topic 的重复 lesson 合并——最重要（其次最新）的条目存活，其余软删除。

## 明确不做的事（设计决定）

- **不做技能定时归档**。旧实现按 `use_count == 0` + mtime 超期把 agent 技能送回收站，已被移除，原因记录在模块 docstring：
  - 度量错了东西——`skill_view` 也加 `use_count`，"被读过"与"被提供过匹配任务却被忽略"无法区分；
  - 按计时器销毁工作，会话里没有信号，用户无从知道技能为何消失；
  - 曾与另一个 90 天归档器并存互不知情，同一技能背两个过期日，更狠的那个说了算。
- 保持索引精简现在是**创作决策**而非 cron：蒸馏提示词优先更新既有技能而不是造近似重复；技能管理工具在创建时报告相似技能；真正死掉的技能由模型显式删除。

## 约束

- 定时器粗粒度，**绝不在会话 turn 内运行**——整理不给聊天加延迟。
- 每个动作可恢复：只软删除，永不硬删。
